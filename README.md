# BroTeam

Локальное приложение для ежедневной работы команды с несколькими agile-досками [Yandex Tracker](https://tracker.yandex.ru). Tracker остаётся местом, где живут задачи. BroTeam собирает их в один рабочий стол: кто чем занят прямо сейчас, что изменилось с прошлого взгляда и что человек успел за период.

Репозиторий: [github.com/ensatum/broteam](https://github.com/ensatum/broteam).

## Скачать

Linux: AppImage и deb. macOS: zip для Intel и Apple Silicon, без подписи Apple. На Mac при первом запуске — ПКМ → Открыть.

Последний релиз: [github.com/ensatum/broteam/releases/latest](https://github.com/ensatum/broteam/releases/latest). Там лежат пакеты Linux и macOS.

## Зачем

У команды несколько досок, и картина дня в самом Tracker размазана по ним. На планёрке и в течение дня нужно быстро ответить на другие вопросы:

- у кого сколько задач и в каких статусах;
- что зависло без ревьюера или тестировщика, что долго стоит в колонке, что уехало в чужой спринт;
- что появилось или сменило статус с прошлого обновления;
- чем конкретный человек занимался за выбранный период и сколько времени задачи провели в статусах.

BroTeam держит эти ответы в одном окне и не требует заходить на каждую доску отдельно.

## Рабочий стол

Окно делится на доски. У каждой доски своя таблица, свой список задач и общие для всех досок сводка и заметки.

**Таблица** — матрица «участник × статус». Строки — люди команды, плюс «Не назначено» и «Остальные». Колонки — статусы доски в том порядке, в каком они настроены. В ячейке число задач. Под таблицей открывается список этих задач: описание, последний комментарий, примечание и закладка.

**Сводка** считается за период по всем включённым доскам сразу. Человек выбирается в шапке сводки, период задаётся календарём, кнопка «Сформировать» забирает из Tracker историю задач за эти даты.

**Заметки** — локальные черновики. В Tracker они не уходят.

## Что видно на доске

Переключение досок — вкладки сверху. У вкладки свой цвет. Состав строк, колонки и фильтры у каждой доски свои.

Над таблицей — спринт и три числа: неготовые задачи, готовые и все. По ним таблица сужается до выбранного круга.

Фильтры слева режут таблицу по спринту, исполнителю, ревьюеру, тестировщику и автору. Значение можно закрепить или исключить. «Не назначено» — отдельный пункт. Счётчики фильтров считаются по всей доске, а не по уже отфильтрованному спринту.

В ячейке, кроме числа, могут стоять метки: нет ревьюера, нет тестировщика, задача долго стоит в колонке, задача из другого спринта, с прошлого обновления что-то изменилось. Колонке в настройках можно дать тег «Разработка», «Тесты» или «Ревью». Для «Тесты» и «Ревью» отсутствие этой роли заметнее.

Список под таблицей раскрывает задачу: ключ, название, описание и последний комментарий. Описание и комментарий запоминаются до ручного обновления этой задачи или полного обновления досок. Непрочитанное изменение помечается плашкой. Текст плашки — то, что BroTeam увидел между двумя загрузками: новый комментарий, «Статус A → B», «Задача обновлена». После просмотра формулировка не подменяется короткой. «Новая задача» ставится только задаче, которую Tracker создал после прошлого обновления доски.

Обновить можно одну задачу или все доски. Задача без исполнителя после точечного обновления остаётся в строке «Не назначено».

Режим «Редактировать таблицу» прячет лишние строки и колонки с этой доски. Пока он включён, фильтры и нижние панели убираются, чтобы не мешать раскладке.

## Сводка

Сводка отвечает на вопрос «что этот человек делал за период», а не «что на нём висит сейчас».

Задача попадает в сводку, если в выбранном периоде человек был исполнителем, ревьюером или тестировщиком либо сам менял задачу. Пустой исполнитель задачу не выбрасывает: на части досок работу делает AI, а человек указан в другой роли.

По каждой задаче есть время в статусах. «Часы (личные)» — время, когда задача была на этом человеке. «Часы (общие)» — время задачи в статусе целиком, его видно, когда личное и общее расходятся. Статус, который задача уже прошла, но без записанного времени, показывает 0. Статус, до которого она ещё не дошла, показывает прочерк.

Кнопка «+ цели» подбирает задачи, которых в сводке ещё нет: для разработчика — колонки «Разработка», где он исполнитель, и «Ревью», где он ревьюер; для тестировщика — колонки «Тесты», где он тестировщик. Готовые задачи в цели не попадают.

Кнопка трансляции, слева от выбора участника, включает режим «только задачи этого человека» на таблицах всех досок. Учитываются автор, исполнитель, ревьюер и тестировщик. Над таблицей появляется плашка с именем; крестик на ней режим выключает. Трансляция и цели живут до закрытия окна и на диск не пишутся.

В списке участников сводки только те, у кого в настройках включена галочка «Сводка».

## Что хранится на компьютере

Задачи, статусы и комментарии читаются из Tracker. Локально лежат настройки, последняя загруженная матрица каждой доски, сводка, примечания к задачам, закладки и заметки. База не зависит от каталога сборки.

- Linux: `~/.config/bro-team/`
- macOS: `~/Library/Application Support/bro-team/`

Если своей базы ещё нет, при первом запуске подхватывается каталог старой установки: `tracker-standup`, `BroTeam` или `BroTracker`.

Настройки, задачи, сводку и заметки можно выгрузить и забрать обратно через «Импорт / экспорт».

## Настройки

- **Приложение** — как часто подтягивать доски и когда сохранять снимок.
- **Интеграции** — OAuth-токен Tracker и Cloud Org ID. Те же параметры, что у MCP-сервера Tracker.
- **Участники** — люди команды: разработчик, тестировщик, менеджер, AI, контакт. Скрытый участник не занимает строку. Галочка «Сводка» решает, попадёт ли он в выбор сводки.
- **Доски и колонки** — поиск доски по названию, ключу очереди или id без учёта регистра. У колонки цвет, порядок и тег роли.
- **Импорт / экспорт** — файл `bro-team-backup`.

## Разработка

Нужны Node.js 20+ и npm. Модуль `better-sqlite3` собирается под Electron, не под системный Node.

```bash
npm install
npm run dev
```

Проверка типов: `npm run typecheck`.

## Сборка

Релиз собирается под Linux и macOS. Linux — AppImage и deb, macOS — zip для Intel и Apple Silicon. Каталог пакетов — `release/`.

`npm run release` останавливается, если `changelog/unreleased.md` не пуст. Иначе собирает тексты коммитов сборки с прошлого тега в новый файл `changelog/год.релиз.md`, коммитит его в `develop`, перематывает `main` на этот коммит, собирает пакеты и ставит тег. Номер версии и этот файл при релизе не меняются. Пакеты в git не входят: их прикрепляют к странице релиза. Ссылка выше открывает последний опубликованный релиз.

`npm run build:dev` собирает в `develop`. Если тег текущего номера уже есть, увеличиваются релиз и сборка. Если прошлая публикация была сборкой, растёт только сборка. Текст из `changelog/unreleased.md` становится телом коммита, сам файл коммит оставляет пустым.

Локальная сборка без релиза: `npm run dist:linux`, `npm run dist:mac`. В пакет попадает бинарь только той системы, для которой он собран.
