# BroTeam

Локальное приложение для ежедневной работы команды с несколькими agile-досками [Yandex Tracker](https://tracker.yandex.ru). Задачи остаются в Tracker. BroTeam собирает их в один стол: кто чем занят, что изменилось и что человек успел за период.

Репозиторий: [github.com/ensatum/broteam](https://github.com/ensatum/broteam).

## Скачать

Linux: AppImage и deb. macOS: zip для Intel и Apple Silicon, без подписи Apple. На Mac при первом запуске — ПКМ → Открыть. Windows: zip для x64, без подписи. Windows SmartScreen предупредит, запуск — через «Подробнее».

Последний релиз: [github.com/ensatum/broteam/releases/latest](https://github.com/ensatum/broteam/releases/latest).

## Зачем

- у кого сколько задач и в каких статусах;
- что зависло без ревьюера или тестировщика, долго стоит в колонке или уехало в чужой спринт;
- что появилось или сменило статус с прошлого обновления;
- чем человек занимался за период и сколько времени задачи провели в статусах.

## Рабочий стол

Окно делится на доски. У каждой свои таблица, список задач и фильтры. Сводка и заметки общие.

**Таблица** — участник на статус. Строки — люди, «Не назначено» и «Остальные». В ячейке число задач. Клик открывает список. Справа колонки FLOW и TOTAL: неготовые задачи строки и все её задачи.

**Сводка** считается за период по всем включённым доскам. Участник выбирается в шапке. Дата — кнопка с календарём, день берётся целиком. «Посмотреть» открывает уже собранное, если выбранные даты в него входят. «Сформировать» заново забирает историю из Tracker. Период, который пересекается с уже собранным, стирает прежнюю сводку. Одновременно идёт один сбор: новый останавливает предыдущий, кнопка стоп гасит текущий.

Внизу слева — сколько запросов ушло в Tracker с последнего обновления досок и за сегодня. Корзина обнуляет оба счётчика.

**Заметки** — локальные черновики. В Tracker они не уходят.

## Доска

Вкладки сверху переключают доски. У вкладки свой цвет.

Над таблицей — спринт, обновление этой доски и три числа: неготовые, готовые и все. Число сужает таблицу до этого круга. Если у колонки выбран тег «Финал», готовые — задачи в таких колонках. Если тега нет ни у одной колонки, готовые — задачи в завершённом статусе Трекера. Переключатель «Готовые» в списке прячет тот же круг.

Фильтры слева: спринт, исполнитель, ревьюер, тестировщик, автор. Значение можно закрепить или исключить.

В ячейке, кроме числа, могут быть метки: нет ревьюера, нет тестировщика, задача давно стоит, чужой спринт, изменение с прошлого обновления, сумма Story Points.

В списке — ключ, название, люди, примечание и закладка. Иконка эпика перед статусом бледная без эпика и синяя с ним; подсказка показывает ключ и название. Та же иконка на панели поиска оставляет в списке задачи одного эпика. Story Points задаются бегунком и пишутся в Tracker. Цветной статус открывает переходы доски. Если переход требует дату, плашка её спрашивает. Другое обязательное поле называется, и переход не уходит. Имена исполнителя, ревьюера и тестировщика меняют человека в Tracker. Описание и последний комментарий открываются кнопками, в комментарий можно дописать свой. Примечание общее для всех досок.

Обновить можно одну задачу, эту доску или все доски. Новая колонка появляется сама, старые не переставляются.

«Редактировать таблицу» прячет пустые строки и колонки и даёт перетащить колонки и группы. Колокольчик группы включает автопропуск изменений сразу для всех её колонок. «Перекрёстные задачи» добавляет в подсчёт задачи других очередей, которые лежат и на этой доске. Первое включение сначала обновляет все доски. Просмотренное изменение гаснет везде, где есть эта задача.

## Сводка

Сводка отвечает, что человек делал за период, а не что на нём висит сейчас.

Задача входит один раз, даже если лежит на нескольких досках. «Активность» — по задаче за период что-то произошло. «Планы» — задача стоит в колонке с тегом, а активности не было. Без участника это все такие задачи, с участником — его действия и его планы. «Косвенно» у выбранного участника оставляет задачи, где он не исполнитель, не ревьюер, не тестировщик и не автор и не менял описание, но менял людей, Story Points или комментарии.

Карточка умеет то же, что карточка в списке: статус, люди, Story Points, эпик, описание, комментарий и примечание. Рамка золотая у активности и серая у планов. В развороте видно последнее действие и часы по статусам: общие и, для выбранного человека, личные.

Трансляция слева от участника оставляет на всех досках только его задачи. Крестик, «Все» и закрытие окна её выключают. В список участников попадают те, у кого в настройках стоит «Сводка». Порядок запоминается.

## Что хранится на компьютере

Из Tracker читаются задачи, статусы и комментарии. На компьютере лежат настройки, последняя матрица каждой доски, сводка, примечания, закладки и заметки.

- Linux: `~/.config/bro-team/`
- macOS: `~/Library/Application Support/bro-team/`
- Windows: `%APPDATA%\bro-team`

Если своей базы ещё нет, первый запуск забирает каталог старой установки: `tracker-standup`, `BroTeam` или `BroTracker`.

«Импорт / экспорт» выгружает и забирает настройки, задачи, сводку и заметки.

## Настройки

- **Приложение** — как часто подтягивать доски и когда сохранять снимок.
- **Интеграции** — OAuth-токен Tracker и Cloud Org ID.
- **Участники** — разработчик, тестировщик, менеджер, AI, контакт. Скрытый не занимает строку. «Сводка» пускает его в выбор сводки.
- **Story Points** — цвет, короткая строка и пояснение для чисел 0, 1, 2, 3, 5, 8, 13 и 21. На доску попадают по «Сохранить». «Восстановить» только заполняет форму.
- **Доски и колонки** — доски ищутся по названию, ключу очереди или id. У колонки цвет, порядок и тег: Разработка, Ревью, Тесты, ИИ или Финал. Колонка принимает выбранные для неё статусы очередей. Группа собирает колонки рядом и может свернуться в одну ячейку. Пишется кнопкой «Сохранить доски».
- **Импорт / экспорт** — файл `bro-team-backup`.

## Разработка

Нужны Node.js 20+ и npm. Модуль `better-sqlite3` собирается под Electron, не под системный Node.

```bash
npm install
npm run dev
```

Проверка типов: `npm run typecheck`.

## Сборка

`npm run release` собирает пакеты Linux, macOS и Windows в `release/` и ставит тег. `npm run build:dev` собирает Linux-билд. Локально, без тега: `npm run dist:linux`, `npm run dist:mac`, `npm run dist:win`. В пакет попадает бинарь только той системы, для которой он собран.

`make` без цели печатает справку. `make build` и `make release` делают то же, что команды npm. `make open` запускает последний пакет. `WHAT=release` берёт релиз, `TYPE` выбирает `appimage`, `deb`, `mac` или `win`, `ARCH` — архитектуру macOS, если архивов два.
