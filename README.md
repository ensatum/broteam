# BroTeam

Локальное приложение для ежедневной работы команды с несколькими agile-досками [Yandex Tracker](https://tracker.yandex.ru). Tracker остаётся местом, где живут задачи. BroTeam собирает их в один рабочий стол: кто чем занят прямо сейчас, что изменилось с прошлого взгляда и что человек успел за период.

Репозиторий: [github.com/ensatum/broteam](https://github.com/ensatum/broteam).

## Скачать

Linux: AppImage и deb. macOS: zip для Intel и Apple Silicon, без подписи Apple. На Mac при первом запуске — ПКМ → Открыть. Windows: zip для x64, без подписи. Windows SmartScreen предупредит, запуск — через «Подробнее».

Последний релиз: [github.com/ensatum/broteam/releases/latest](https://github.com/ensatum/broteam/releases/latest). Там лежат пакеты Linux, macOS и Windows.

## Зачем

У команды несколько досок, и картина дня в самом Tracker размазана по ним. На планёрке и в течение дня нужно быстро ответить на другие вопросы:

- у кого сколько задач и в каких статусах;
- что зависло без ревьюера или тестировщика, что долго стоит в колонке, что уехало в чужой спринт;
- что появилось или сменило статус с прошлого обновления;
- чем конкретный человек занимался за выбранный период и сколько времени задачи провели в статусах.

BroTeam держит эти ответы в одном окне и не требует заходить на каждую доску отдельно.

## Рабочий стол

Окно делится на доски. У каждой доски своя таблица, свой список задач и общие для всех досок сводка и заметки.

**Таблица** — матрица «участник × статус». Строки — люди команды, плюс «Не назначено» и «Остальные». Колонки — статусы доски в том порядке, в каком они настроены. В ячейке число задач. Под таблицей открывается список этих задач: примечание, закладка, а описание и последний комментарий — по кнопкам в развёрнутой карточке.

**Сводка** считается за период по всем включённым доскам сразу. Человек выбирается в шапке сводки. Дата периода — кнопка, она же открывает календарь. День берётся целиком, с полуночи до полуночи. «Посмотреть» показывает уже собранную сводку, если каждая выбранная дата в неё входит. «Сформировать» заново забирает из Tracker историю задач за эти даты. Если новый период хоть где-то пересекается с уже собранной сводкой, прежняя стирается и сбор идёт с пустого места. Одновременно идёт только одно формирование: новое останавливает предыдущее. Кнопка стоп на кружке гасит этот сбор, и он сам не продолжается.

Внизу слева — сколько запросов ушло в Tracker с последнего обновления досок и за сегодня. Корзина слева от этих чисел обнуляет оба счётчика.

**Заметки** — локальные черновики. В Tracker они не уходят.

## Что видно на доске

Переключение досок — вкладки сверху. У вкладки свой цвет. Состав строк, колонки и фильтры у каждой доски свои.

Над таблицей — спринт, по центру кнопка обновления этой доски, и три числа: неготовые задачи, готовые и все. По числам таблица сужается до выбранного круга. Кнопка забирает из Tracker только открытую доску.

Фильтры слева режут таблицу по спринту, исполнителю, ревьюеру, тестировщику и автору. Значение можно закрепить или исключить. «Не назначено» — отдельный пункт. Счётчики фильтров считаются по всей доске, а не по уже отфильтрованному спринту.

В ячейке, кроме числа, могут стоять метки: нет ревьюера, нет тестировщика, задача долго стоит в колонке, задача из другого спринта, с прошлого обновления что-то изменилось. Колонке в настройках можно дать тег «Разработка», «Тесты» или «Ревью». Для «Тесты» и «Ревью» отсутствие этой роли заметнее.

Список под таблицей раскрывает задачу: ключ, название, люди и примечание. В развёрнутой карточке слева дата, статус и люди, справа плашка изменения, под ней примечание, и по центру этой половины кнопки описания и последнего комментария. Текст запоминается до ручного обновления этой задачи или полного обновления досок. Разметка Трекера в них видна как текст: плашки, свёртки, рамки и таблицы. Непрочитанное изменение помечается плашкой. Текст плашки — то, что BroTeam увидел между двумя загрузками: новый комментарий, «Статус A → B», «Задача обновлена». После просмотра формулировка не подменяется короткой. «Новая задача» ставится только задаче, которую Tracker создал после прошлого обновления доски.

Обновить можно одну задачу, текущую доску или все доски. Обновление доски добавляет статус, которого ещё не было в колонках: задача в нём сразу видна, прежние колонки не переставляются. Задача без исполнителя после точечного обновления остаётся в строке «Не назначено».

Режим «Редактировать таблицу» прячет лишние строки и колонки с этой доски. Пока он включён, фильтры и нижние панели убираются, чтобы не мешать раскладке.

## Сводка

Сводка отвечает на вопрос «что этот человек делал за период», а не «что на нём висит сейчас».

Задача попадает в сводку один раз, даже если она лежит на нескольких досках. Без выбранного участника «Активность» — задачи, по которым за период что-то произошло, «Планы» — задачи в колонках с тегом, где активности не было. С участником остаются те же две кнопки: его собственные действия и его планы в колонках с тегом. Задача, где участник за период ничего не делал и которая не стоит у него в плане, в список не входит.

Рамка карточки золотая у активности и серая у планов. Задача в колонке с тегом «Разработчик» обведена зелёным. Если выбранный участник — автор задачи, слева на карточке бледно-зелёная полоса. В развёрнутой карточке статус крупнее остального текста. Строка «Последнее действие» — самое свежее изменение задачи, кто его сделал и когда. Описание, последний комментарий и таблица времени по статусам открываются кнопками под именами. Описание и комментарий показывают ту же разметку Трекера, что и список.

Без выбранного участника колонка называется «Часы (общие)»: всё время задачи в каждом статусе, включая смены до выбранного периода. Текущий статус идёт до сейчас. С участником рядом появляется «Часы (личные)» — часть этого времени, когда задача была на нём: исполнителе, ревьюере или тестировщике. Задача без смены статуса всё равно попадает в список, если за период был комментарий, реакция или другое изменение. Статус, до которого задача ещё не дошла, показывает прочерк. Уже собранная сводка показывает прежние часы, пока её не сформируют заново.

Кнопка трансляции, слева от выбора участника, включает режим «только задачи этого человека» на таблицах всех досок. Учитываются автор, исполнитель, ревьюер и тестировщик. Над таблицей появляется плашка с именем; крестик на ней режим выключает. Сброс участника и выбор «Все» тоже выключают трансляцию. Пока трансляция включена, смена участника выбирает в таблице ячейку Total строки Total. Трансляция живёт до закрытия окна и на диск не пишется.

В списке участников сводки только те, у кого в настройках включена галочка «Сводка». Стрелки слева от имени меняют их порядок, он запоминается на этом компьютере.

## Что хранится на компьютере

Задачи, статусы и комментарии читаются из Tracker. Локально лежат настройки, последняя загруженная матрица каждой доски, сводка, примечания к задачам, закладки и заметки. База не зависит от каталога сборки.

- Linux: `~/.config/bro-team/`
- macOS: `~/Library/Application Support/bro-team/`
- Windows: `%APPDATA%\bro-team`

Если своей базы ещё нет, при первом запуске подхватывается каталог старой установки: `tracker-standup`, `BroTeam` или `BroTracker`.

Настройки, задачи, сводку и заметки можно выгрузить и забрать обратно через «Импорт / экспорт».

## Настройки

- **Приложение** — как часто подтягивать доски и когда сохранять снимок.
- **Интеграции** — OAuth-токен Tracker и Cloud Org ID. Те же параметры, что у MCP-сервера Tracker.
- **Участники** — люди команды: разработчик, тестировщик, менеджер, AI, контакт. Скрытый участник не занимает строку. Галочка «Сводка» решает, попадёт ли он в выбор сводки.
- **Доски и колонки** — поиск доски по названию, ключу очереди или id без учёта регистра. У колонки цвет, порядок и тег роли.
- **Импорт / экспорт** — файл `bro-team-backup`.

## Разработка

Нужны Node.js 20+ и npm. Модуль `better-sqlite3` собирается под Electron, не под системный Node.

```bash
npm install
npm run dev
```

Проверка типов: `npm run typecheck`.

## Сборка

Релиз собирается под Linux, macOS и Windows. Linux — AppImage и deb, macOS — zip для Intel и Apple Silicon, Windows — zip для x64. Каталог пакетов — `release/`.

`npm run release` останавливается, если после последней сборки есть ещё не собранные коммиты задачи. Иначе собирает их заголовки из коммитов сборки с прошлого тега в новый файл `changelog/год.релиз.md`, коммитит его в `develop` как `chore(release): год.релиз`, перематывает `main` на этот коммит, собирает пакеты и ставит тег. Номер версии и этот файл при релизе не меняются. Пакеты в git не входят: их прикрепляют к странице релиза. Ссылка выше открывает последний опубликованный релиз.

`npm run build:dev` собирает в `develop` и не забирает незакоммиченные правки. Если тег текущего номера уже есть, увеличиваются релиз и сборка. Если прошлая публикация была сборкой, растёт только сборка. Коммит называется `build: compile release artifacts for год.релиз.сборка`. В теле — заголовки коммитов задачи с прошлой сборки. Их прогноз лежит в `changelog/unreleased.md` и этим коммитом очищается.

Локальная сборка без релиза: `npm run dist:linux`, `npm run dist:mac`, `npm run dist:win`. В пакет попадает бинарь только той системы, для которой он собран.

Из корня репозитория то же самое вызывает `make`. Команда без цели печатает справку.

`make build` собирает билд: AppImage появляется в `builds/`, коммит уходит в `develop`. `make release` собирает релиз: пакеты ложатся в `release/`, ставится тег.

`make open` запускает последний билд. По умолчанию это AppImage. `WHAT=release` открывает последний релиз. `TYPE` выбирает файл: `appimage`, `deb`, `mac` или `win`. Если архивов macOS два, архитектуру задаёт `ARCH`, например `make open WHAT=release TYPE=mac ARCH=arm64`. AppImage запускается. Пакет deb открывает установщик системы, zip — программа архива.
